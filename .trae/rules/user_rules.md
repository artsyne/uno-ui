# 用户编码标准与重构指南
# 基于 Martin Fowler 的《重构》

## 基本交互规则
1. 请用中文回复我
2. 提供代码时，为关键点和难以理解的部分添加中文注释
3. 当生成的代码超过20行时，考虑整合代码并评估粒度是否合适

## 代码质量与重构标准

### 通用编码标准
1. 避免不必要的对象复制或克隆
2. 避免深层嵌套；改用提前返回
3. 使用适当的并发控制机制

## 代码坏味道识别与处理

基于 Martin Fowler 在《重构》中的核心见解，以下是需要注意的代码坏味道及其处理方法：

### 1. 神秘命名（Mysterious Names）
- **问题**：变量、函数、类或模块名称没有清楚地表达其目的和含义
- **解决方案**：使用描述性名称重命名，使代码自解释
- **示例**：将 `fn p()` 改为 `fn calculate_price()`

### 2. 重复代码（Duplicate Code）
- **问题**：相同或相似的代码出现在多个地方
- **解决方案**：提取到函数、类或模块中；应用模板方法模式
- **示例**：将重复的验证逻辑提取到共享函数中

### 3. 过长函数（Long Functions）
- **问题**：函数过长，难以理解和维护
- **解决方案**：提取函数，将大函数分解为多个较小的函数
- **示例**：将200行的处理函数分解为几个单一职责的函数

### 4. 过大的类/结构体（Large Class/Struct）
- **问题**：类或结构体承担过多职责，字段和方法过多
- **解决方案**：提取类，将相关字段和方法分组到新类中
- **示例**：从 User 类中提取地址相关字段到 Address 类

### 5. 过长参数列表（Long Parameter Lists）
- **问题**：函数参数过多，难以理解和使用
- **解决方案**：引入参数对象，将相关参数组合成对象
- **示例**：将 `fn create_user(name, email, phone, address, city, country)` 改为 `fn create_user(user_info: UserInfo)`

### 6. 发散式变化（Divergent Change）
- **问题**：一个类因多种不同原因而被修改
- **解决方案**：根据变化原因拆分类
- **示例**：将同时处理数据库操作和业务逻辑的类拆分为两个独立的类

### 7. 霰弹式修改（Shotgun Surgery）
- **问题**：一个变化需要在多个类中进行修改
- **解决方案**：将相关功能移到同一个类中
- **示例**：将分散在多个类中的订单处理逻辑整合到单一的 OrderProcessor 类中

### 8. 依恋情结（Feature Envy）
- **问题**：一个函数对其他类比对自己的类更感兴趣
- **解决方案**：移动函数或提取函数
- **示例**：将大量使用另一个类数据的方法移到那个类中

### 9. 数据泥团（Data Clumps）
- **问题**：相同的数据项总是一起出现
- **解决方案**：提取到对象中
- **示例**：将经常一起出现的开始和结束日期提取到 DateRange 类中

### 10. 基本类型偏执（Primitive Obsession）
- **问题**：使用基本类型来表示具有特定含义的数据
- **解决方案**：用小对象替换基本类型
- **示例**：用 PhoneNumber 类替换电话号码字符串

## 重构过程原则

### 1. 小步重构
- 一次只做一个小改动，然后测试
- 频繁提交，保持代码始终可工作

### 2. 测试安全网
- 重构前确保有足够的测试覆盖
- 每次改动后运行测试，确保行为不变

### 3. 代码审查
- 重构后进行代码审查以确保质量
- 分享重构经验以提高团队能力

## 代码可读性优化

### 1. 命名约定
- 使用有意义的描述性名称
- 遵循项目或语言的命名标准
- 避免缩写和单字母变量（除了循环中的 'i' 等约定俗成的）

### 2. 代码组织
- 将相关代码放在一起
- 函数应该只做一件事
- 保持适当的抽象层次

### 3. 注释与文档
- 注释应该解释为什么，而不是做什么
- 为公共 API 提供清晰的文档
- 更新注释以反映代码变化

## 性能相关重构

### 1. 内存优化
- 避免不必要的对象创建
- 及时释放不再需要的资源
- 注意内存泄漏问题

### 2. 计算优化
- 避免冗余计算
- 使用适当的数据结构和算法
- 延迟计算直到必要时

### 3. 并行化优化
- 识别可以并行化的任务
- 避免不必要的同步
- 注意线程安全问题
