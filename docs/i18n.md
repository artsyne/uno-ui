# Internationalization (i18n)

Uno ships eleven locales and exposes them through the `i18n` Alpine store. Components read
their labels and messages from that store; application code can read and extend it too.

## Bundled locales

All locales are imported into the bundle at startup, so no network request is needed to switch
between them.

| Code | Language |
| :--- | :--- |
| `en` | English (fallback) |
| `zh-CN` | Simplified Chinese |
| `zh-TW` | Traditional Chinese |
| `es` | Spanish |
| `ja` | Japanese |
| `de` | German |
| `fr` | French |
| `ko` | Korean |
| `pt` | Portuguese |
| `ru` | Russian |
| `ar` | Arabic |

The message tree is:

```text
box.ok
box.cancel
box.loading
box.close
valid.required
valid.pattern
valid.min
valid.max
valid.counter
valid.range
valid.rangeMin
valid.rangeMax
valid.match
valid.compareto
valid.tagMax
valid.callback
valid.validname
valid.en
valid.domain
valid.mobile
valid.int
valid.email
valid.date
valid.url
valid.pwd
valid.strongpwd
valid.summary_title
charCount
```

Not every key is consumed by the current components. `box.close`, `valid.required`,
`valid.pattern`, `valid.min`, `valid.max`, `valid.counter`, `valid.rangeMin`,
`valid.rangeMax`, `valid.match`, the standard validator messages (`valid.email`, `valid.url`,
`valid.date`, `valid.int`, `valid.validname`, `valid.en`, `valid.domain`, `valid.mobile`,
`valid.pwd`, `valid.strongpwd`), and `valid.summary_title` are used today. The remaining keys
are available for custom validators or future components.

Box `okText` and `cancelText` are rendered literally; they are not translated automatically.
Translate them in your application before passing them, or override the strings globally:

```javascript
Uno.setConfig({
  plugins: {
    box: { okText: 'Confirm', cancelText: 'Cancel' }
  }
})
```

## Store API

```javascript
const i18n = Alpine.store('i18n')
```

| Member | Type | Description |
| :--- | :--- | :--- |
| `locale` | `string` | Current locale code. |
| `messages` | `object` | Messages keyed by locale. |
| `loading` | `boolean` | True while `loadLocale()` is fetching. |
| `t(key, vars)` | `string` | Look up a dot path and interpolate `{name}` placeholders. Missing keys return the key itself. |
| `setLocale(lang)` | `void` | Switch to a loaded locale and persist it. |
| `setLang(lang)` | `void` | Alias of `setLocale`. |
| `extend(messages)` | `void` | Deep-merge additional messages, including new locales. |
| `loadLocale(lang, url)` | `Promise<void>` | Fetch a JSON locale and activate it. |

### `t()`

```javascript
Alpine.store('i18n').t('valid.min', { n: 3 }) // "At least 3 characters"
```

- Keys are dot paths: `box.close`, `valid.email`.
- Placeholders use `{word}` (letters, digits and underscore).
- A missing key returns the key unchanged.
- A missing variable leaves `{word}` in the output.
- If the current locale is missing, the English dictionary is used.

### `setLocale()` and `setLang()`

```javascript
Alpine.store('i18n').setLocale('zh-CN')
Alpine.store('i18n').setLang('zh-CN') // alias
```

The value is normalized before lookup:

- `_` becomes `-`; matching is case-insensitive.
- `zh`, `zh-Hans-*` → `zh-CN`.
- `zh-Hant-*`, `zh-HK`, `zh-MO` → `zh-TW`.
- Other regional variants fall back to their base language when it is registered
  (`ja-JP` → `ja`, `pt-BR` → `pt`).
- Unknown codes are not switched; a warning is logged.

On success the code is written to `localStorage` under the key `uno.lang`.
Uno does not modify `<html lang>`; set that attribute from your server template or application.

### Detection order

At startup `locale` is chosen as follows:

1. `localStorage.getItem('uno.lang')`, if it normalizes to a bundled locale.
2. `navigator.language`, then each entry in `navigator.languages`.
3. `en`.

### `extend()`

`extend()` deep-merges messages into the existing store. It can override keys or add a new
locale:

```javascript
Alpine.store('i18n').extend({
  en: {
    box: { ok: 'Yes', cancel: 'No' }
  },
  it: {
    box: { ok: 'Conferma', cancel: 'Annulla', loading: 'Caricamento', close: 'Chiudi' },
    valid: { required: 'Campo obbligatorio' }
  }
})

Alpine.store('i18n').setLocale('it')
```

New locales added through `extend()` are immediately usable with `setLocale()`.

### `loadLocale()`

`loadLocale()` fetches a JSON file at runtime. The JSON file must contain the same shape as the
bundled locale modules.

```javascript
await Alpine.store('i18n').loadLocale('it', '/locales/it.json')
```

```json
{
  "box": { "ok": "Conferma", "cancel": "Annulla", "loading": "Caricamento", "close": "Chiudi" },
  "valid": {
    "required": "Campo obbligatorio",
    "email": "Indirizzo email non valido",
    "summary_title": "Correggi i seguenti problemi"
  }
}
```

Notes:

- The result of `normalizeLocale()` is used as the key. A regional code that normalizes to an
  already-loaded locale (`fr-CA` → `fr`) returns immediately and is **not** loaded as a
  separate variant. Use a distinct base code, or use `extend()` for variants.
- The request uses `fetch`; it fails on `file://` pages.
- A failed request is logged through `log.error` and leaves the current locale unchanged.
- The function resolves to `undefined`; check `Alpine.store('i18n').locale` afterwards if you
  need to confirm the switch.

## `x-t` directive

`x-t` writes a translation into the element:

```html
<button x-t="box.close"></button>
<button x-t.aria-label="box.close"></button>
<span x-t="charCount"></span>
```

- Without modifiers, the text is written to `textContent`.
- With modifiers, each modifier is treated as an attribute name and receives the translation.
  `x-t.aria-label` is the common example.
- The directive is reactive: it re-evaluates when `locale` changes.

## Adding a bundled language

A new bundled locale is a source change and requires a rebuild:

1. Create `src/locales/<code>.js` with the same object shape as `src/locales/en.js`.
2. Import it in `src/core/i18n.js` and add it to `initialMessages`.
3. Run `npm run build` and commit the updated `dist/` (the repository tracks it; CI checks it).
4. Run `npm run test:run`.
5. Add the code to this page and to the `CHANGELOG.md` entry for the release.

Regional variants are normalized as described above; do not add a regional key unless it
really needs different text from its base language.

## RTL

`ar` is a right-to-left locale. Uno's default classes use logical properties (`ms-`, `me-`,
`start-`, `end-`) and the tooltip position calculation mirrors left/right for RTL anchors.
Uno does not set `dir` on the document; your application must set `<html dir="rtl">` (or a
wrapper) and Tailwind must see the corresponding classes.
