# Content Security Policy (CSP)

Uno has a small CSP hook: a configured nonce is written to the containers it creates and to
`<style>` elements created through `Uno.dom.injectStyles()`. That is the full extent of the
built-in support. It does **not** make an Alpine application compatible with every CSP, and it
does not remove Alpine's expression-evaluation requirements.

## What Uno does

Configure the nonce before the first component creates a container:

```javascript
Uno.setConfig({
  csp: { nonce: window.__CSP_NONCE__ }
})
```

With a nonce configured:

- `Uno.dom.ensureContainer()` writes `nonce="..."` on each container it creates
  (`uno-box-manager`, `uno-notify-container`, `uno-tooltip-manager`, and the progress bar).
  CSP does not evaluate nonces on `<div>` elements; the attribute is there for consistency
  with the style hook and for integrations that inspect it.
- `Uno.dom.injectStyles(id, css)` writes the nonce on the created `<style>` element.
- No built-in component calls `injectStyles()` today, and no component injects `<script>`.
  There is no script-nonce injection to configure.

The nonce is read from `Uno.options.csp.nonce` at element-creation time. Set it before the
first `box.open()`, `notify.show()` or tooltip render; setting it afterwards only affects
containers and styles created later.

## What you still need

### Alpine expression evaluation

Uno's templates contain Alpine expressions (`x-show`, `:class`, `x-init`, callback arrows,
object literals). The standard Alpine 3 build evaluates expressions with `new Function`, so a
policy that blocks `'unsafe-eval'` will break the components even when the script files
themselves are allowed.

A typical nonce-only deployment therefore still needs `'unsafe-eval'` for the standard Alpine
build. That is a real weakening of the policy; do not describe such a deployment as
"strict CSP".

Alpine also publishes a CSP build with a restricted expression language. Uno has not been
tested against it, and its templates use expressions that a restricted evaluator may reject
(arrow functions, method calls, object literals). Treat it as unsupported unless you validate
every component you use.

### Tailwind CSS

Uno ships no CSS. Component classes are generated by your Tailwind build, so the normal
`style-src` rules for your application's stylesheet apply. The `@tailwindcss/browser@4`
prototype build injects a `<style>` element at runtime; a strict `style-src` needs to allow it
(or use a build-time stylesheet instead).

### The rest of the page

`default-src`, `connect-src` (HTMX/fetch), `img-src`, `font-src` and `form-action` remain your
application's responsibility. Uno makes no claim about a complete policy.

## Example: Express with per-request nonce

```javascript
import crypto from 'node:crypto'
import express from 'express'

const app = express()
app.set('view engine', 'ejs')

app.use((req, res, next) => {
  res.locals.nonce = crypto.randomBytes(16).toString('base64')
  res.setHeader(
    'Content-Security-Policy',
    [
      "default-src 'self'",
      `script-src 'self' 'nonce-${res.locals.nonce}' 'unsafe-eval' https://cdn.jsdelivr.net`,
      `style-src 'self' 'nonce-${res.locals.nonce}'`
    ].join('; ')
  )
  next()
})

app.get('/', (req, res) => {
  res.render('index', { nonce: res.locals.nonce })
})
```

```html
<!-- views/index.ejs -->
<script nonce="<%= nonce %>">
  window.__CSP_NONCE__ = '<%= nonce %>'
</script>
<script src="/vendor/uno-ui/dist/uno.umd.js" defer></script>
<script src="/js/uno-config.js" defer></script>
<script src="https://cdn.jsdelivr.net/npm/alpinejs@3.17.3/dist/cdn.min.js" defer></script>
```

```javascript
// /js/uno-config.js
window.Uno.setConfig({
  csp: { nonce: window.__CSP_NONCE__ }
})
```

`'unsafe-eval'` is shown explicitly because the standard Alpine build needs it. Remove it only
if you have replaced Alpine with a build that does not evaluate strings, and verify every Uno
component you use.

## Debugging CSP failures

| Symptom | Likely cause | Check |
| :--- | :--- | :--- |
| `Refused to evaluate a string as JavaScript` | Missing `'unsafe-eval'` (standard Alpine). | Browser console; the blocked expression. |
| `Refused to apply inline style` | A runtime style build is blocked. | Use a build-time stylesheet, or allow the nonce/`'unsafe-inline'` for that source intentionally. |
| Components render but do nothing | Alpine never started or expressions were blocked. | Check `window.Alpine`, `window.Uno`, and CSP console errors. |
| Nonce mismatch | The nonce in the header and in `Uno.setConfig()` differ. | Render one value per response; do not cache the HTML and the header separately. |
| Works with `Content-Security-Policy-Report-Only` | The policy is in report-only mode. | The browser reports but does not block; inspect the reports. |

## Reporting-only rollout

Use `Content-Security-Policy-Report-Only` first, collect violations, and only then enforce.
A nonce or `'unsafe-eval'` decision should be based on the actual reports from the components
and integrations you use.
