# Uno UI Framework Review

## 概览 (Overview)

Uno UI 是一个基于 Alpine.js, HTMX 和 Tailwind CSS 的 UI 组件库。经过代码审查，该框架目前的实现方式处于 "Vanilla JS 插件" 和 "Alpine.js 组件" 的混合状态。

虽然它利用了 Alpine.js 的插件注册机制，但在核心组件的实现上，大量依赖了命令式的 DOM 操作（`document.createElement`, `innerHTML`, `classList.add`），而没有充分利用 Alpine.js 的响应式特性（Reactivity）和声明式语法（Declarative Syntax）。

为了符合现代 Alpine.js 生态系统的最佳实践，并为开源做好准备，建议进行以下重构。

## 详细审查 (Detailed Review)

### 1. 核心架构 (Core Architecture)

- **现状**: 目前组件多以函数形式存在，通过 `Alpine.magic` 或 `Alpine.store` 暴露，但内部逻辑大量使用了原生 JS 的查询和操作。
- **问题**: 这种方式丧失了 Alpine.js "数据驱动视图" 的优势。用户很难通过修改数据来更新 UI，必须调用特定的 JS 方法。
- **建议**: 
    - 将状态管理移至 `Alpine.store`（对于全局状态如 Modal, Notify）。
    - 将组件逻辑移至 `Alpine.data` 或 `Alpine.directive`。
    - UI 渲染应完全由 HTML 模板 + Alpine 指令（`x-if`, `x-for`, `x-bind`）控制，而非 JS 拼接字符串。

### 2. 组件审查 (Component Review)

#### Box (Modal/Dialog)
- **文件**: `src/components/box/box.js`
- **发现**: 
    - 使用 `document.createElement` 动态构建 DOM。
    - 手动管理 Event Delegation。
    - 使用 `innerHTML` 插入内容。
- **Alpine 约定偏差**: 
    - Alpine 推荐使用 `<template x-teleport="body">` 来处理模态框。
    - 状态（是否显示、标题、内容）应保存在 Store 中，视图层通过 `x-show="$store.box.open"` 响应。
- **HTMX 集成**: 
    - 目前使用自定义的 `ajax.js` 获取内容。
    - **建议**: 支持 `hx-get` 加载模态框内容，或者让模态框容器成为 HTMX 的 `hx-target`。

#### Notify (Toast/Notification)
- **文件**: `src/components/notify/notify.js`
- **发现**: 
    - 使用了 `Alpine.data`，这很好。
    - 但 Loading Indicator 和 Progress Bar 仍然是通过 `document.createElement` 注入的全局元素。
    - 使用方式较为局限，通常 Toast 需要全局调用（如 `Uno.notify.success(...)`），目前实现似乎依赖于页面上存在特定的 `x-data="notify"` 元素。
- **建议**: 
    - 使用 `Alpine.store('notifications', { items: [] })` 管理消息队列。
    - 提供一个全局的 `<div x-data x-for="item in $store.notifications.items">` 容器来渲染消息。
    - 这样可以在任何地方通过 `$store.notifications.add(...)` 触发通知。

#### Tab (Tabs)
- **文件**: `src/components/tab/tab.js`
- **发现**: 
    - 完全是 Vanilla JS 实现，使用 `document.querySelectorAll` 查找 DOM。
    - 依赖 `data-tab-target` 等属性。
- **Alpine 约定偏差**: 
    - 这是最适合用 `x-data="{ active: 'tab1' }"` 实现的组件。
    - **建议**: 重构为 `Alpine.data('tabs', ...)`，通过 `:class` 切换样式，通过 `x-show` 切换内容。

#### Tooltip
- **文件**: `src/components/tooltip/tooltip.js`
- **发现**: 
    - 使用 `Alpine.data`。
    - 需要用户编写复杂的 HTML 结构。
- **建议**: 
    - Tooltip 通常更适合用 **指令 (Directive)** 实现。
    - 例如: `<button x-tooltip="'Hello World'">Hover me</button>`。
    - 使用 `Alpine.directive('tooltip', ...)` 可以极大地简化用户代码，且库内部可以使用 Tippy.js 或 Floating UI (或者自己实现定位逻辑)。

#### Valid (Form Validation)
- **文件**: `src/components/valid/valid.js`
- **发现**: 
    - 手动操作 DOM class (`!border-red-500`)。
- **建议**: 
    - 使用 Alpine 的 `:class` 绑定。
    - 结合 HTML5 原生验证 API 和 Alpine 的 `x-model`。

### 3. HTMX & Tailwind 生态兼容性

- **HTMX**: 
    - 目前框架与 HTMX 的交互较少。
    - **建议**: 确保所有组件（特别是 Box 和 Tab）都能很好地处理 HTMX 注入的新内容（使用 `htmx.onLoad` 或 `htmx.process` 初始化新内容中的 Alpine 组件）。
- **Tailwind CSS**: 
    - 样式类名硬编码在 JS 中。
    - **建议**: 提供配置选项允许覆盖默认类名，或者将样式提取到可配置的 `theme` 对象中。

## 总结与改进计划 (Summary & Roadmap)

Uno UI 目前更像是一个依赖 Alpine.js 作为加载器的 jQuery 插件集。为了成为一个真正的 Alpine.js UI 框架，建议进行以下重构：

1.  **重写 Box**: 改用 `Alpine.store` + `x-teleport`。
2.  **重写 Tab**: 改用 `x-data` + `x-show`。
3.  **重写 Tooltip**: 改用 `Alpine.directive`。
4.  **移除 DOM 操作**: 尽可能移除所有 `document.createElement` 和 `innerHTML`，改用数据驱动。
5.  **增强 HTMX 支持**: 增加对 HTMX 事件的监听，确保组件在 HTMX 替换内容后能自动初始化。
